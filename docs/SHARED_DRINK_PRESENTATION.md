# 客厅一起喝东西：动作标杆

更新：2026-09-19。本文描述本轮有限表演层，不把画面计时当作生活模拟结算。

## 玩家看到什么

- 邀请／等待：两人站在椅旁，一人邀请、另一人留出回应时间。尚未参与时不会自行坐下喝完。
- 已经参与：先后走近、坐稳，前倾拿杯，喝一口，再将杯子放回桌面。之后保持坐姿交流，不无限循环举杯。
- 已完成：放杯、起身、离开。它是对已发生事实的收尾展示，不因此重复获得关系或资源收益。
- 拒绝：拒绝者摇头、转身离开；邀请者收回动作，双方不播放成功庆祝。
- 中断／未约成：保持各自分支，不冒充共同活动完成。
- 减少动态效果：直接显示该事实阶段的稳定姿态，杯子留在桌上，不强制播放移动过程。

这组演出只消费服务端公开的 `shared_drink` 阶段、参与者和饮品种类。普通聊天不会被前端擅自变成喝茶事件。

## 为什么调整了桌椅尺寸

复用了现有 KayKit 椅子和矮桌，两类现有人物不换身份、不拉长骨头。椅面约 0.388 世界单位，桌面约 0.6，杯子靠各自座位的桌边，水平距离约 0.511。旧桌面过低且过远，真实骨架无法自然触达，单纯提高 IK 强度不能解决。

坐下时将臀部与实际座面对应，并对脚踝作有限地面接触修正。取杯时先前倾约 37 度，再校正手到杯柄的接触；杯子提起后跟随实际腕骨，放下时回到同一桌面位置。说话时使用保留坐姿下肢的上身动作，而不是重新站起来。

同一套家具位置用于客厅和近景。管理端移除、更换为不兼容家具或将桌椅移得过远时，不强行跨房间取杯；降回普通交流。场景刷新、对白下一句和轮询不会反复重启有限演出。

## 验证入口

开发夹具：`/scripts/fixtures/embodied-life.html`，无需账号，不调用 AI，不写存档。

- `?phase=active&family=city&time=6.5`：城市人物在指定秒数的姿势。
- `?phase=active&family=chibi&time=6.5`：Chibi 同一动作检查。
- `&clean=1`：隐藏验收工具条，检查手机原始布局。
- 顶部切换邀请、等待、参与、完成、拒绝、中断及未约成；动画选项可选择跟随系统、减少或完整。

固定时间只在开发构建生效，不是生产调试入口。它不会冻结或推进真实世界时间。

自动检查已接入 Web lint：

- 七个事实阶段、两名演员、120 秒采样和减少动态效果；确认动作最后停稳、拒绝分支不喝东西、杯子不会随离场消失。
- 加载两类实际 GLB 骨架，检查默认取杯目标腕骨误差小于 12 毫米、坐姿脚踝与含鞋厚目标相差小于 4 厘米、骨骼长度不变。
- 家具编辑后接触位置与可用性检查。

这些是逻辑／资产数值守卫，不等价于两分钟连续视觉验收或手机真机性能测试；实际截图和浏览器验证记录由本轮总交接记录补充。

## 明确边界

- 这是一个精细化场景标杆，不是通用全身 IK 或任意物体抓握系统。取杯接触范围围绕兼容的桌椅限定。
- 没有新增手指抓握骨骼动画、真实液体、嘴唇语音同步或物理杯子。杯柄与腕骨对齐不等于每根手指都闭合。
- 现有两套角色比例仍不同，未擅自将玩家人物替换为统一人物；接触误差数值不能保证所有衣服边缘都没有穿模。
- 近景是公开事件阶段的有限展示，不与 AI 每个单词或服务器每一秒严格同步。活动完成仍以服务器真实行动和共同参与时长为准。
- 阅读、做饭等其他生活动作仍沿用既有实现，不能据此宣称所有日常动作都达到这一标准。
