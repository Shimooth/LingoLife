# 下一轮视觉优化：先让人物真正生活在场景里

更新时间：2026-09-19。依据本地代码、真实生活片段画面，以及桌面／390px 手机预览。下列是长期验收目标；本轮已并行实现客厅喝饮品的第一条完整样板，具体范围和限制见下节，不表示所有场景都已完成。

## 本轮落地：共享客厅里的双人喝饮品

- 玩法先行：居民有明确茶／咖啡兴趣，在公共客厅出现合适共同活动机会，才可能提出邀请。明确不喝、戒除、过敏等描述不会被反当兴趣。活动仍服从居民意愿、需求和已有安排，不保证每次登录都发生。
- 引擎分别公开邀请、等候、实际参与、完成、拒绝、中断、没约成七种事实阶段。AI 只生成对应事实的英文对白和中文翻译，不得决定动作完成或替换饮品、参与者。
- 演出包括椅旁邀请、接近、坐下、前倾取杯、喝一口、放回、倾听，以及起身离开等分支。喝完不无限重播整套动作；下一句对白和世界刷新不重置整个演出。
- 手杯接触和座面／脚部约束作用于两套已有骨架，不拉伸骨头；桌椅高度与杯位来自实际模型和布局。管理员删除、换成不支持的桌椅，或把它们放得太远时，退回普通交流，不虚构椅子或跨房间抓杯。
- 同一演出已接入生活片段和住宅实况。实况要求两人同一活动、同一位置且都在实际参与，避免把邀请对象提前摆到椅子上；参与者不再重复绘制。
- 普通生活片段区分说话与倾听、身体朝向和拒绝情绪；不再每句重挂整个人物或将开心一律演成跳跃。脚边姓名对应实际人物，场景摘要移到画面下方；窗外统一为低模城市景观。
- 城市预设中的 12 个可安全分离原生眼睛，支持五种轻表情、错开眨眼和细微视线。City-04/07/15/16 保留原样；Chibi 实测压眼会露眼窝，已禁用压缩／眨眼，只保留轻微视线。没有实现嘴型同步，也没有改掉已有玩家外观。资产依据见 `CHARACTER_FACE_ASSET_AUDIT.md`。

### 怎样查看与验收

- 正常游戏：居民有合适兴趣和共同空闲时自然产生新活动；历史生活片段不会被强行改写成喝茶。
- 独立场景：`http://127.0.0.1:5173/scripts/fixtures/embodied-life.html`，可切七阶段、两套角色和减少动画；`?phase=active&family=chibi&time=6.5` 固定取样方便查接触。固定时间仅开发环境生效。
- 住宅实况：`http://127.0.0.1:5173/scripts/fixtures/visual-review.html?activity=drink_break`。
- 面部近景：`http://127.0.0.1:5173/scripts/fixtures/facial-preview.html`。
- 动作与数值验收的实现说明见 `SHARED_DRINK_PRESENTATION.md`。
- 夹具使用虚构人物和手写验收台词，不登录、不扣 AI 额度、不改玩家数据；真实玩法链另由后端测试验证，不能把夹具台词当作模型输出质量证明。

这仍是第一条标杆场景，不是通用全身 IK、手指抓握或全部爱好动作升级。现有角色两套画风尚未彻底统一，未做真正手机 GPU／十分钟热稳定性验证。后续优先复制到一起吃饭、递物和争执后的离开，而非继续增加无对应行为的随机动作。

## 结论

目前的“简陋”不主要来自模型面数。城市资产可以继续使用；更明显的问题是角色风格不统一、动作与物件接触不真实、人物表情不足，以及背景和舞台像是拼起来的。

**推荐先完成一个高品质的双人生活场景，再扩充其他场景和动作。** 不建议现在批量换成高面数人物、再叠一层重滤镜；那样可能更清晰地暴露穿模和比例问题。

| 层面 | 目前实际表现 | 玩家为什么觉得不自然 |
| --- | --- | --- |
| 角色风格 | 16 个城市人物预设与一套可换装 Chibi 并存，比例、脸部细节和服装题材不同 | 同一场景像混用了两款游戏的人物 |

## 实施优先级与验收标准

### 第一优先：双人表演，而不是再加几十个随机动作

先做“在客厅邀请对方一起喝东西／聊天”这一组完整演出。动作随事件事实展开：走近、停稳、看向对方、邀请、等回应；接受就坐下继续，拒绝就收回动作、让开或离开。不能所有分支都笑着挥手结束。

- 说话的人有手势，听的人有视线和细小回应，避免同时大幅摆动。
- 身体先转向，再移动；停下时有减速和重心回稳。
- 杯子从桌面拿起、拿到手里、放回桌面，不凭空消失。
- 坐下和站起使用过渡动作，坐稳时身体与座面贴合。
- 保留现有骨架动作库，重点补齐缺少的动作段和接触约束；不为了数量添加无法对应玩法的动作。

验收：静音观察也能区分邀请、接受、犹豫、拒绝；连续观看两分钟没有明显手穿杯子、脚滑、椅子穿身或突然换姿势。同一事件在两种不同性格组合上有不同节奏，但不篡改实际结果。

### 第二优先：统一角色外观，并补上脸部表演

先制作两名“标杆居民”。确定统一的头身比例、眼睛风格、衣料质感和肤色照明，再选择保留哪一套角色作为未来的主风格。旧角色不应未经玩家选择被换成另一个人。

- 日常服装优先，减少骑士／忍者等服装与普通城市生活的违和。
- 最小表情集：自然、开心、不满、困倦、疑惑，以及独立眨眼和看向目标。
- 先检查模型是否有可用的眼睛／眼皮／嘴部骨骼或形态键；没有就需要修改或替换脸部资产，不能靠几个参数凭空生成。
- 近景才播放细表情，远景保留姿态与少量状态图标。

验收：不看头顶表情图标也能判断主要情绪；两人站在一起像同一个世界的人；近景不出现塑料过亮、眼睛发黑或皮肤失去层次。

### 第三优先：做一个完整、可信的室内空间

先把共享住宅客厅做成品质样板。以桌椅、沙发、窗户为主体，增加书、杯子、靠垫等有生活用途的小物件，而不是把房间填满。

- 人物身高决定椅面、桌面和门窗尺寸，停止为构图分别随意缩放人物与家具。
- 生活片段直接利用房间座位和物件位置，减少独立“人物舞台”。
- 窗外景色统一低模／绘本化方向，不把写实建筑图与低模家具硬叠。
- 每个房间有主光方向、柔和填光和接触阴影；重点保持人物脸部可读。

验收：住宅漫游和生活片段看见的是同一套空间逻辑；人物确实能坐在可见椅子上；桌面物件不会堵路；画面缩成手机大小仍能辨认行为。

### 第四优先：镜头和信息设计

- 对话以人物和正在使用的物件为主体，摘要不长期抢占表演空间。
- 两人交流使用稳定的双人构图，重要回应才轻微调整；不随每句话切镜头。
- 普通情绪不一直挂大图标；关键拒绝、惊讶或新事件再短暂强调。
- 结果用一句事实提示；管理操作才说明接受、拒绝或适得其反，不做任务评分式结算。

验收：手机 390px 宽、长姓名、双语对白都不挡脸、不挡操作；回看历史不重复弹出同一条结果；减少动画设置下仍完整可用。

### 第五优先：城市质感与移动性能

保留现有城市建筑资产，优先统一街道尺度、街区密度、植被分组和建筑配色。增加车流之后，下一步是合理的街角、门口和人物活动点，而不是无限增加车辆。

性能优化围绕近景和远景分配细节：选中人物保留高品质动作和阴影，远处人物降低动画更新频率；重复家具／街景复用资源；按需要加载室内。先做固定镜头对比，再进行真实手机测试。

建议验收目标：目标手机连续游玩十分钟仍稳定、触控跟手、不明显降质闪烁。具体帧率和显存预算要用设备实测决定；当前 Chrome 手机尺寸预览不能代表手机 GPU 性能。

## 本轮已完成：加载恢复与简洁结果

- 本地后台曾出现健康接口正常、数据库相关请求不返回的状态。原 Python 3.9 进程采样停在 macOS 系统 SQLite 的 `purgeableCacheShrink`；这说明阻塞位置，不足以断定该系统库存在某个已知缺陷。
- 本地已切换到项目内独立的 Python 3.12 / SQLite 3.53.2 环境，保留原虚拟环境和数据库。启动器对旧 Python 命令自动转交新版环境；新机器没有新版环境时明确报版本要求，不继续错误启动。
- 另修复旧存档存在居民、但对应可编辑角色资料缺失时，物品标签补全直接索引资料导致的异常。
- 对白请求共享一个 60 秒等待上限；只轮询尚未完成的同一版本；版本变化立即退出旧请求；支持跳过等待、明确失败、手动重试。重试后的查询不会反复授权付费生成。
- 生活片段移除底部常驻结果卡和强制滚动。最后一句播放后，弹出实际活动／关系／资源变化的短提示，约 6.5 秒后收起，支持关闭。鼠标悬停或键盘聚焦时暂停收起；同标签页内回看同一结果不反复提示。刷新页面后会重新建立本页的提示记录。
- 历史存档和服务端结果数据未删除；长结果卡组件仍留在代码中，但已不再用于生活片段窗口。引导的显式完成步骤保留，不因提示消失而自动完成。
- 本轮没有大规模更换模型、动作或美术风格，也没有部署。
