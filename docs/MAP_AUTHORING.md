# 3D 天空之城与共享住宅作者工具

- 版本：0.3
- 产品决定更新：2026-09-03
- 状态：管理端城市/住宅 placement 编辑、3D 预览、服务端草稿、统一拓扑校验、不可变发布历史与回滚已实现；独立作者角色和运行中资源租约迁移待实现

该工具用于开发和运营人员使用项目中已经授权、转换并通过运行时检查的资产编辑城市与唯一共享住宅。它不是普通玩家玩法，也不能直接修改 NPC 的动态世界事实。

## 1. 权限与入口

目标入口位于独立管理端，由专门的布局作者权限保护。管理端其他账号可以继续只读查看运营数据；只有获授权的开发/运营人员能够创建草稿、预览、校验、发布和回滚。

首版已经把编辑器放入现有管理端，并使用既有管理员 HttpOnly Cookie、Origin 检查和独立写 API；普通玩家域名不展示作者 UI，玩家端只有 published layout 只读接口。当前尚未细分“内测运营管理员”和“布局作者”角色，管理端编辑代码也仍随 Admin 页面直接加载，这两项属于上线多人运营前的权限与分包硬化。

## 2. 两种编辑模式

### 2.1 城市布局

支持使用批准资产编辑：

- 道路、路口和三条外向云路；
- 建筑及业务地点语义；
- 唯一共享住宅在城市中的位置；
- 树木、花坛、灌木、长椅、路灯、消防栓、车辆和其他街道小品；
- NPC 人行区域、地点入口和镜头聚焦锚点。

### 2.2 共享住宅布局

当前只维护一套正式品质的共享住宅，供每个玩家世界的 2～8 名活跃居民共同使用。编辑范围包括：

- 客厅、厨房、浴室、卧室和必要过渡空间；
- 墙、地面、门、窗、家具和装饰；
- 电视、料理台、浴室、床、餐桌、储物等语义资源；
- 房门、路径节点、交互站位、朝向、摄像机和隐私遮挡区域；
- Life Action 与动画接触需要的语义锚点。

本阶段不创建第二套可切换住宅主题，也不为每个公共建筑制作完整可进入室内。质量预算优先用于这一套住宅的灯光、构图、材质、动线、动作接触与移动端可读性。

## 3. 资产目录

编辑器只显示资产清单中已批准的模型。每项资产至少记录稳定 ID、来源与许可证、运行时文件、类别、包围盒、占地、可旋转/缩放范围、碰撞类型、LOD/性能级别及允许场景。

布局只保存稳定资产 ID 和受约束变换，不保存本机路径、任意外部 URL、脚本、Prompt 或用户上传文件。视觉模型可以迭代替换，但地点、房间和资源等服务端语义 ID 不随模型文件名变化。

当前白名单覆盖 KayKit 道路、A～H 建筑、车辆/街道设施/绿化以及已导入的家具、厨房、浴室、餐饮和植物模型；`config/world-asset-catalog.json` 进一步为全部 62 个唯一模型记录来源、许可证、类别、完整 bounds/footprint、LOD、允许图层和语义能力。schema 拒绝任意 URL、额外字段、重复 ID、未知/重复/缺失的业务地点映射、缺少唯一 shared-home、越界坐标和不完整基础房间。共享住宅的正式默认场景由 `config/shared-home-layout.json` 记录房间、资产占地、厨房/电视/浴室资源、13 类 Life Action 站位、2/4/8 人容量和 8 个明确私人床位；前端默认场景、后端 placement 和发布校验共同复验该合同。当前管理端仍只编辑 placement，不能直接创作新的语义 anchor 合同。

## 4. 统一空间校验

放置、移动、旋转、导入、预览和发布必须调用同一版本的校验规则。

城市至少校验：

- 道路相邻接口双向匹配、全路网连通和三条云路出口保留；
- 建筑完整位于合法地块、至少一侧临路且不压路；
- 平台边界、建筑、固定设施、装饰、居民站位和行程区域不发生非法重叠；
- 共享住宅、业务地点入口和摄像机焦点都能解析到同一权威布局。

住宅至少校验：

- 所有非私密房间可从入口到达，门和路径不被家具封死；
- 资源容量、包围盒、交互站位和朝向有效；
- 13 类首轮 Life Action 所需资源/地点锚点全部存在；
- 2、4、8 名居民均有合法私人房间/床位映射和共享区域站位；
- 隐私行为不会把角色模型或隐藏资源信息暴露给城市视图；
- 镜头在桌面和移动端能看到关键角色与资源。

非法操作只显示可定位的问题，不覆盖已发布布局。任何 error 级问题都会阻止发布。

## 5. 草稿、预览、发布与回滚

当前已经实现正式发布闭环：

- 服务端只有一个全局草稿，写入必须携带 `revision`；过期编辑器得到 409 CAS 冲突，不能静默覆盖新草稿；
- 保存草稿会运行同一纯拓扑验证器并持久化结构化问题，但允许保存尚未修完的草稿；发布会再次运行该验证器，任何错误都会阻止 active 指针变化；
- 发布内容以规范 JSON 的 SHA-256 作为不可变版本身份；重复发布相同内容只重新激活既有版本，不改写最初的作者、说明或创建时间；
- active 是单例指针；回滚通过校验并重新激活历史版本，不覆盖或删除任何版本；
- publish、重复内容激活、历史激活都保存作者、说明、前后版本和时间审计；
- 默认恢复同样发布/激活一个已验证的代码默认版本，历史版本继续保留。

仍待实现的是独立于通用管理员 Cookie 的布局作者角色，以及布局删除正在占用的资源时对租约和 Life Action 的安全迁移。

- 草稿保存作者、创建时间、父版本、布局类型、schema/rules 版本和变更说明；
- 预览使用隔离的模拟快照，不影响在线玩家；
- 校验通过后发布为不可变版本，玩家世界只引用 published version；
- 激活新版本前备份当前 active version，并检查运行中资源租约和 Life Action；
- 若锚点被删除或移动，服务端只能按规则完成、中断或重新规划行为，不能由编辑器直接传送 NPC；
- 回滚是重新激活一个已验证版本，不是覆盖或删除历史版本；
- 所有发布、激活和回滚进入审计日志。

## 6. 与生活模拟的边界

作者工具可以改变“世界允许什么”：道路、地点、房间、资源、容量、路径和视觉布局。

作者工具不能直接改变：

- NPC 的当前位置、情绪、需求、Desire、Commitment 和 Life Action 结果；
- 方向性关系、恋爱状态、记忆、秘密和 Unresolved Thread；
- Moment / Incident / Story Thread 的参与者、窗口或结算；
- 世界时间、稳定种子、学习进度和 AI 额度。

布局变更影响后续候选行为和碰撞概率，但所有变化必须经过服务端权威状态机。普通玩家未来可能获得受规则约束的家具管理动作，也不能直接复用这个拥有全城发布权的作者工具。

## 7. 当前首版操作与迁移

管理端提供两个编辑模式：

- 城市：道路、建筑、街道设施和绿化/装饰四层，可拖拽、调整坐标/朝向/统一缩放、复制、删除，并在 3D 预览中选择；
- 共享住宅：living room、kitchen、bathroom、bedroom 四个固定房间，可使用批准室内资产编辑 placement 并预览；
- JSON 可导出备份，也可导入为当前浏览器里的未发布编辑态；可以分别保存服务器草稿、查看拓扑问题和填写发布说明；
- 发布历史显示哈希、作者、说明、创建时间与 active 状态，历史版本可以用“激活 / 回滚”重新启用；
- 玩家端通过只读 world-layout API 取得当前 published manifest；没有数据库配置时使用代码内置默认布局。

玩家端旧 `?mapEditor=1` 入口已经移除，正式编辑只从已鉴权管理端进入。涉及路网或场景的正式变更除首版 schema/API 检查外，仍需进入版本库并运行：

```bash
cd web
npm run check:world-roads
npm run check:world-decorations
npm run check:world-navigation
npm run check:world-camera
```

旧 `localStorage` 或外部 JSON 不得直接信任，必须导入编辑器并经过服务端 schema 与完整拓扑校验。旧数据库中的 `world_layout_configs(scope='published')` 会在增量 schema v4 初始化时迁移为第一个不可变版本并设为 active，不删除原数据。

## 8. 验收标准

### 8.1 当前实现

- 未持有管理员会话的请求不能读取管理布局或调用写 API；普通玩家只能读取 published layout；
- 城市和共享住宅均能用批准资产编辑、预览、保存服务器草稿、重新打开、发布和 reset；
- 任意 URL、额外字段、未知资产/地点、重复 ID、断路、非法云路出口、完整 footprint 压路/碰撞、缺失 shared-home/业务地点、城市越界、室内不可达、fixture/action/resource anchor 缺失和容量不足都会产生结构化问题并阻止发布；
- 发布 payload 不包含 NPC 动态字段；自动化表指纹证明发布失败、发布成功、激活与回滚均不写 NPC、关系、消息、学习、住宅资源、Desire、Life Action 或故事事实；
- CAS 冲突、内容哈希幂等、不可变版本、历史激活、默认恢复和管理 Cookie/Origin 边界都有 API 测试。
- 代码内置默认布局只有一个 shared-home 建筑，并包含四个已有资产 placement 的住宅房间。

### 8.2 正式生产作者工作流

- 未授权管理账号和所有普通玩家均无法读取草稿或调用布局写 API；
- 编辑器资产面板不出现未批准资产，payload 注入 URL/脚本/NPC 动态字段会被拒绝；
- 城市断路、建筑压路、设施冲突和越界不能发布；
- 住宅不可达、资源锚点缺失、站位碰撞和 2/4/8 人容量不足不能发布；
- 发布和回滚后，角色、关系、记忆、故事、学习数据与已结算结果完全保留；
- 新布局只能通过下一次权威世界推进影响路径、资源可用性和候选行为；
- 单套共享住宅在桌面和移动端完成视觉、交互、隐私与性能验收。
