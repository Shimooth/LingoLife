# NPC 生活对白：从拼台词改为整段创作

2026-09-15，本地实现，并追加失败恢复与界面精简；未提交、未推送、未部署。本文取代旧说话风格文档中关于生活片段和玩家开场的“纯模板”描述，不代表共餐面板的所有阶段提示也已替换。

## 玩家会感受到什么

- 同样是“来找室友聊天”，安静的人可以明确说想独处，活泼的人可以打趣，但来访者和被拜访者不能混淆。
- 不是固定念五句。独处是 1～3 句自言自语，多人交流是 2～8 句，英文和中文一起编写。
- 每句显示“谁 → 对谁说”，人物标签补充“来访者／正忙的居民”“做饭的人／用餐的人”等身份。
- 对白按性格、兴趣、习惯、边界、双方熟悉／紧张程度，以及当前发生的事实创作。兴趣不代表当前正在做该活动。
- 结尾应该有原因：尊重边界、作出决定、回去做事，或明确暂时没解决。不是为了凑足句数突然说“那就这样”。
- 玩家介入后，对白描述已经结算的后续；拒绝、误会和反效果不能被写成双方握手言和。
- 点开 NPC 的第一句话也可以由 AI 根据当前公开活动和人设创作；不再只由活动类型选一句固定开场。
- 进城时只加载基础资料，不等待开场创作；真正打开聊天才请求新开场，避免给城市加载额外增加 AI 等待时间。

这里的随机性是“同类处境可以有不同表达”，不是“刷新一下历史就换词”，更不是“AI 为了好玩改写已经发生的事”。

## 一段生活如何变成对白

1. **生活先发生。** 游戏照常安排生活、记录相遇和摩擦、确定实际反应。没有打开事件也会继续生活。
2. **玩家打开片段。** 界面显示编写中的提示。不会因为城市每次刷新、每位 NPC 每次换行动就生成整段剧本。
3. **整理一张场景卡。** 包括人物身份、人设、地点、明确发生的事实、各人的决定、关系氛围。模型不读取整个世界存档、密码或账号资料。
4. **AI 写完整一场，再校对一次。** 校对聚焦身份、事实、承接、翻译和收尾；不得编出未发生的行动、其他场所或过去经历。首稿格式错误时，第二次机会用于修复；每段最多两次调用。
5. **校验并保存。** 检查说话人、听话人、身份、人数、长度、英文／中文、动作白名单。通过后固定保存；失败保留场景信息，提供简短的“对白未加载 · 重试”，不再用五句通用客套冒充正常对白。
6. **播出演出。** 按句显示，当前说话的人播放支持的动作，另一人倾听。生成或观看过程中仍可参与，不让请求耗尽介入窗口。
7. **介入后看后果。** 游戏先结算，新的对白依据真实结果接续。旧对白保留在缓存中，但当前现场不重放旧开头。结果卡仍来自游戏规则，AI 没有改写它的权力。

## 三个已针对性处理的问题

| 原问题 | 新约束 |
| --- | --- |
| 一个角色问完自己，又由自己回答 | 独处只允许独白，听话人必须为空；多人必须指向另一个真实参与者 |
| 来访者／被访者反了 | 从碰撞事实中的发起者、目标和忙碌状态生成身份；旧数据给双方分配同类“下次再来”意图时，被访者的表达解释为“现在没空”，不反过来扮演来访者 |
| 吃完突然提洗碗，又强制结束 | 明确做饭者和用餐者；不重复邀请吃已消费的食物、不编造已洗碗／答应洗碗；结尾需对应当前问题 |

注意：本轮纠正的是表达层对旧意图的解释，没有借机重做碰撞规则的行为分配或关系结算。

## 事实与创作的边界

允许：不同措辞、犹豫、调侃、主观感受、表达当前已确定的意愿。

不允许：没有证据的“我查过两次时间”“你刚才把锅刮干净了”“泳池关了”，以及凭空指定书的章节、食材、之前到访、精确约定时间等。

首轮真实 DeepSeek 抽检发现：仅靠“别编造事实”的一句提示仍会出现这些细节，而且把其他片段的台词用来防重复，会让模型误当成共同记忆。因此已做两项修正：不同事件不共享对白作为创作上下文；增加第二轮事实校对。仅开场使用近期开场文本防止原句重复，并明确它们不是当前场景的事实。

结构校验是确定性的；自然语言事实校对仍然由模型完成，**不能保证零幻觉**。本轮最终 3 场景＋2 开场已成功完成真实双语抽检，但不是对所有情况的保证，尤其还需长期观察恋爱边界、多方争执和介入失败。

## 回放、异常和额度

- 世界继续使用原存档，不重置任何真实账号。
- 新故事创建时冻结可用于表达的人设和关系氛围；旧故事第一次生成时使用当时可得的人设。成功缓存后编辑人设不会重写这段历史。
- 缓存按账号、故事及结果区分；“已看过”和城市轮询不会改变对白。结果变化才生成后续。
- 玩家开场按账号、NPC、游戏日、行动实例隔离；房间入口和正式聊天读取同一份开场。
- 玩家聊天上下文只引用已缓存的实际 AI 对白，未生成的故事只给生活事实，不再把旧模板当成真实发言。
- 重复请求跨进程只会有一个生成者；失效请求不能覆盖已完成或已超时的结果。请求期间不持有世界／数据库锁。
- 失败片段不在每次打开时反复扣费，玩家可点“重试”。每次重试是独立、确定性的缓存分支，保留旧记录及其当日请求预留；并发重试合并，不改变世界结果。成功对白不能通过重试重新抽词。
- 若初稿通过结构校验而校对失败，初稿仅保留在服务端供下一次继续校对，不直接展示为已完成对白。网络失败、模型 HTTP 错误及结构错误分别记录安全错误码，不记录密钥、请求正文或模型原始异常。
- 当日额度用完不能新建重试；跨日再次请求时重新判断可重试状态。失败修复不需要删档或清空全部缓存。
- 与玩家聊天轮次额度分开统计。默认每账号每真实日最多预留 **48 次**模型请求，全站 **1000 次**；每段预留两次，失败不退预留。日期按 `GAME_TIMEZONE`，不是世界模拟时钟。
- `EXPRESSION_DAILY_LIMIT`、`EXPRESSION_GLOBAL_DAILY_LIMIT`、`EXPRESSION_MAX_TOKENS` 可配置；单次默认输出上限 2000 tokens。设预算为 0 只停止新的生成，不清除已缓存对白。
- 缓存保存模型返回的 token 用量（若有）。这些调用目前**不计入旧管理端的聊天次数图表**；预算是保护上限，不是充值余额系统。
- 测试账号重置会清除对应表达缓存；不会删掉账号、邀请码或已有独立聊天额度审计。

## 开发定位

| 位置 | 内容 |
| --- | --- |
| `backend/lingolife/life_expression.py` | 场景卡、身份、提示词、校验、编写／校对、缓存协调 |
| `backend/lingolife/ai.py` | DeepSeek JSON 请求；与现有玩家流式回复分开 |
| `backend/lingolife/db.py` | 表 `life_expression_cache`、跨进程抢占、预算、结果保存 |
| `backend/lingolife/life_world.py`、`interaction.py` | 故事产生时保存人设与关系氛围；游戏行为不调用 AI |
| `POST /api/v1/life-stories/{story_id}/dialogue` | 登录、账号归属、可观察性检查之后按需生成；不接受自定义提示词 |
| `GET /api/v1/room?author_opening=true` | 真正进入聊天时请求开场；默认读取房间不触发新创作，但复用已有缓存 |
| `web/src/life/useSceneDialogue.ts` | 加载／缓存显示、请求超时、取消和过期响应隔离 |
| `web/src/components/LifeStoryEncounter.tsx` | 双语逐句演出、身份、听话人、摘要回退 |

返回包括 `status`（pending/ready）、`source`（ai/fallback）、`cache_key`、`revision`、`roles`、`ending_reason`、`retryable` 和 `presentation`；其中每句包含 `speaker_id`、`addressee_id`、`text`、`translation_zh`、`animation_cue`。没有修改游戏数值的字段。失败重试使用 `POST /life-stories/{story_id}/dialogue?retry=true`，仍需登录并验证故事归属。

## 日常界面做减法

不再常驻“已结算／不是任务评分”“你未介入”“一次回应不等于关系定型”“对白已保存”等实现说明。对白后只显示简短结果和最多两条实际变化；其他个人反应和细节折叠在“查看详情”。删去重复状态卡、阶段标题、场景标题和非对白的双语重复说明。引导期只保留简短下一步，常规游玩不展示规则教学。

## 2026-09-18：身份、借物重复与生活口吻

用户反馈“没有先问就借走了”反复出现、对白像边界沟通示范。检查发现三个独立原因：借物行动被无条件算成越界；物主与借用者从同一回应集合抽签；未观看的旧片段没有退出当前动态的时限。表达层还会把首次观看的已结算事件当成一段已发生对话的后半场。

### 玩法与事实

- 只有明确的借物行动、确实存在且可用的他人物品，以及稳定的“未先询问”判定同时成立，才产生借物越界事件。去别人家看书、做兴趣活动本身不再证明借用了东西。
- 未先问的基准概率为 12%，冲动／莽撞设定为 40%；明确“先问”边界再乘 0.4，同一方向的两人近两天发生过借物冲突再乘 0.25。按行动 ID 稳定判定，轮询不会重抽。这是小范围规则调节，不是 AI 自主授权借用，更不代表存在完整物品流转系统。
- 借用者可以道歉归还、补问、嘴硬；物主可以要求先问、这次允许并提醒、要求归还。明确补问时，物主在允许和要求归还之间作出回应，不再只重复规则。
- 从已保存的个人物品中选择借用对象。新增小规模双语逻辑物品名称（如耳机、速写本、量杯、书签、骰子、充电线，以及随行杯、雨伞、充电宝、帆布袋），不是新 3D 模型。旧物品仅补缺失名称，已有名称不随编辑兴趣改写；历史事件不追加虚构细节。
- 摘要明确“谁没问谁、借了什么”，不再只有“涉及两人、触碰重要边界”的泛泛描述。

### 当前动态与历史

- 同一话题、同一组居民的已结算动态只优先展示最新一条；其他居民组合与仍待介入的事件保留。
- 已记下的生活片段退出当前生活片段栏。创建超过 24 小时的片段，即使没看过，也不再一直占据当前动态；仍在有效介入状态的事件不按此隐藏。
- 只改变当前推荐与展示资格，历史接口、结算、角色关系和存档不删除。原有成功 AI 缓存不清空，已保存的旧对白不会自动变成新对白。

### AI 表达

明确 `borrower`／`owner`，传入真实物品名称、双方决定及中文 `decision_brief`。旧记录里不符合身份的决定不继续交给模型，但不重算旧关系结算。首次观看标记 `first_view`；未有实际 AI 前段对白时不假装“谢谢听我说完”。

创作强调当场接话、有个人立场、不重复客套或宣布人生道理；第二轮使用独立终审提示词，核查初稿而不是继续编写。针对本次抽检发现的擅自许可、嘴硬突然保证改正、补问没有问句、虚构物品位置／找东西经历／使用时长等，加入小范围校验及具体修复提示。仍最多两次调用；不通过则显示摘要，不把错误台词当作事件事实。

这些是针对已发现问题的护栏，不是通用语义证明器。其他说法仍可能逃过检查，不能宣称 AI 永不编造。跨多次事件的长期故事延续仍是后续工作，本次没有把全部生活模拟改成无限自由生成。
