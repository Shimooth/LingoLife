# 一起喝东西：客厅与咖啡馆动作标杆

更新：2026-09-26。本文描述有限表演层，不把画面计时当作生活模拟结算。

## 继续打磨：交谈、倾听和椅边换步

- NPC 生活片段的站立交谈、饮品完成后的坐谈接入 UAL 专门上身动作。保留底层站姿／坐姿，不再通过反复切换拼接的 `Seated_Interact` 让手臂停在末帧。动作有淡入和收势；倾听者不再随机抽到大幅摆臂的待机。
- 对白文字可以一直留在记录中，但角色的说话表演只持续该句的有限时段；最后一句后回到安静姿态。相同片段的轮询不会重播；减少动态效果时不启动表演。没有新增字幕、解释卡或玩家提示。
- 杯子离桌、靠近嘴边、放回和走路时，不叠加说话手势；杯柄接触优先，喝水时不同时张嘴说话。桌边倾听轻点头跟随实际发言轮次，不再每 6.8 秒机械重复。
- 椅旁对齐、起身后离开的转向新增有限两步落脚：一脚支撑、一脚抬起后转向落下，再换脚；目标来自真实模型的安静站距，起点来自当前可见走路／站起姿态。首次更新不必恰好是时间零点，不能将抬起的脚瞬移压到地面。
- 生活动画在演出计时器挂载前准备就绪，人物骨架未加载时不推进动作。否则第一次 walk → life 的资源等待会吃掉大部分 0.4 秒转身，数值求解器即使正确也来不及工作。
- 交接时保留最后行走采样时间，并先从上一帧可见脚位建立支撑，再推进姿态混合，避免两帧额外陷地。转身的膝盖弯曲方向连续过渡，不每帧读取接近伸直的原始膝盖方向，防止脚位没动但脚踝突然拧转。
- 转身是本场景的程序式接触改良，不是新录制的专用转身动画，也不是全城任意地形的足部锁定系统。保留原事实阶段和动作时长，不把表演进度用来结算事件。

新增复验：`node scripts/check-social-motions.mjs`、`node scripts/check-social-performance.mjs`、`node scripts/check-standing-turn.mjs`。浏览器连续复验：`node scripts/check-social-motion-browser.mjs`、`node scripts/check-arrival-motion-browser.mjs`；需本地 Vite 和隔离 Chrome CDP 19226。前两个入口的来源与边界见 [动作素材计划](CHARACTER_MOTION_ASSET_PLAN.md)。

无需账号的预览：`http://127.0.0.1:5173/scripts/fixtures/social-motion.html?case=standing`（站谈）、`?case=seated`（坐谈）、`?case=arrival`（走近、换步、坐稳，可点击收尾离开）。支持 `&family=chibi` 和 `&reduced=1`。验收对白为手写示例，不证明 AI 台词质量。

## 坐姿验收纠正：臀部支撑优先，不强拉脚到地面

上一轮手杯接触和连续播放通过，并不代表坐姿正确。用户指出“没有完全坐下来”后，低机位侧面复查确认两处缺陷：

- 把骨盆节点加固定高度对齐椅面，不等于可见臀部坐上椅子。City 的 `Hips` 甚至比真正的大腿根低约 12cm，不能拿它直接代替臀部支撑点。
- 原接地修正同时转动大腿和小腿，把脚向大腿根正下方拉。City 原动作大腿近水平，经修正后下斜约 68°，膝盖接近伸直，形成“半站在椅子前”的姿态。

正确约束是：可见臀部／近端大腿先由座面支撑，保留屈膝坐姿，再处理鞋底穿地。腿短、椅子较高时允许自然垂脚，不以“双脚必须碰地”为理由破坏坐姿。坐下和起身仍平滑进入／退出接触，不缩放人物或拉长骨头。新的验收必须检查真实皮肤支撑、侧面大腿角和膝盖角度，不能只检查脚踝高度。

住宅椅面也按实际渲染资产修正：`armchair_pillows` 原始座面为 0.5，默认缩放 0.8 后为 0.400；旧 0.388 是错误标定。咖啡馆自建椅面仍为 0.388。两种家具不再混用一个近似高度。

最终独立侧面验收覆盖两套人物 × 两场景：City 大腿约 1°、膝盖约 110°；Chibi 大腿约 6°、膝盖约 115°。用实际蒙皮和实物椅面射线独立测得近臀身体支撑误差约为 0／1.83mm，修复过程中额外发现并消除了 Chibi 臀腿过渡处 34mm 的穿垫。完整连续播放和手杯回归也通过。短腿悬脚是合理结果，不再试图把它拉成站姿。

## 2026-09-26：连续动作与自然接触打磨

本轮没有更换玩家的模型，也没有下载大包填充动作数量。先修正导致动作不自然的播放和接触问题：

- 走近椅子前先减速、转向，再坐下；起身后转向离开。City 使用抬脚较低的原生 `Walk_B`，Chibi 保留自己的步态；步相跟随行走距离，而不是人物慢移、双脚按固定速度踏步。
- 原生动作和生活动作之间保留上一帧可见姿态，约 220ms 混合；同一循环不会因为调速或下一句对白重播。同一段坐姿的时间贯穿取杯、抬杯、饮用、放杯，不再每个小阶段从零开始。
- 明确执行顺序为“行动目标 → 骨骼 → 实物杯”，避免杯子落后一帧。切换动作的 React 提交尚未完成时，不让旧片段误读新片段的时间。
- 手臂采用有限范围的两骨接触校正，肘部有稳定方向；伸手逐渐接管、收手逐渐交还原动作。手腕从真实到位姿态校准握杯方向，不直接复制杯子的旋转。骨长、缩放与人物外观不变。
- 嘴部锚点在生活动画已经采样的原始坐姿上、施加前倾／低头之前，从真实面部测量；不能在走路骨架上提前缓存，也不能在低头取杯时把额头当嘴。连续验收独立重测当前脸面与杯口，而不拿同一个旧锚点自证对齐；咖啡近景改成更接近双人侧面的镜头，避免近处人物一直背对视线。
- 取放杯使用有弧度的路径，视线先落向杯子再回到对方；倾听只偶尔轻点头。收手返回身侧，不再沿杯柄方向伸到肩膀后面，修复 Chibi 肘部突然翻转。
- 两套身体比例分别限制前倾：City 约 37°，Chibi 约 26°。真实落座后重新检查整个坐姿周期的杯柄可达性，以及 Chibi 头部皮肤与桌面至少 8cm 的垂直净空，不以更深弯腰补偿短手臂。
- 服务端新阶段到来时保留同一人物：尚未坐下就从当前位置离开；坐下一半会先坐稳；正在拿杯则从当前高度放回；杯子已经落桌则直接起身，不重新拿杯演一遍结局。此收尾不拖延服务端结算。

实测步相参数、实际骨架差异和下一批应该加工的素材，见 [人物动作素材计划](CHARACTER_MOTION_ASSET_PLAN.md)。没有专门的起步／收步／原地转身素材，因此当前转向仍是程序过渡，不等于完整的转身脚步动画或全身足部锁定。

## 2026-09-26：真实咖啡馆饮品活动

- 月光咖啡馆、花园咖啡馆内，同住的两名居民实际同地、正在休闲活动，有真实茶／咖啡兴趣且发生 companionship 碰面时，可以提出同一 `drink_break` 邀请。不是所有咖啡馆碰面都会喝饮品；赶路、工作、用餐、不同地点和私人场景不会因此被替换。
- 沿用自愿回应和七阶段。接受不等于已经坐下；双方实际执行各自四分钟饮品行动、共同参与足够时间才完成。离场会中断，拒绝后不会被旧同意重开。没有增加付费 AI 调用或新的模拟循环。
- 正式 `LifeStoryEncounter` 根据故事里已保存的地点、两名参与者和服务端 `shared_drink` 阶段选择咖啡馆近景；普通咖啡馆聊天保持普通演出。居民仍是 `indoor`，不复制到城市地图的外摆座位。
- 近景与地图外摆共用 `CAFE_DRINK_RIG` 和 `CafeDrinkFurniture3D` 的桌椅。近景使用原生尺寸，地图整体缩放；活动中的杯子由表演组件绘制，家具组件不再放重复静态杯。外摆空桌属于街景，不能当作居民正在户外喝咖啡的证据。
- 咖啡桌面高 0.608、座面高 0.388，左右杯位 x=±0.37。实际 City／Chibi 骨架两座位要求手杯误差小于 12 毫米、真实臀腿支撑贴合椅面、保留屈膝且鞋底不穿地；不改变骨长。废弃旧“脚踝必须接近地面目标”的标准，它曾掩盖半站姿错误。
- 客厅继续使用实际编辑后的桌椅定位；缺少或不兼容家具仍退回普通交流。咖啡馆不会套用玩家家里的客厅编辑布局。

## 玩家看到什么

- 邀请／等待：两人站在椅旁，一人邀请、另一人留出回应时间。尚未参与时不会自行坐下喝完。
- 已经参与：先后走近、坐稳，前倾拿杯，喝一口，再将杯子放回桌面。之后保持坐姿交流，不无限循环举杯。
- 已完成：放杯、起身、离开。它是对已发生事实的收尾展示，不因此重复获得关系或资源收益。
- 拒绝：拒绝者摇头、转身离开；邀请者收回动作，双方不播放成功庆祝。
- 中断／未约成：保持各自分支，不冒充共同活动完成。
- 减少动态效果：直接显示该事实阶段的稳定姿态，杯子留在桌上，不强制播放移动过程。

这组演出只消费服务端公开的 `shared_drink` 阶段、参与者和饮品种类。普通聊天不会被前端擅自变成喝茶事件。

## 为什么调整了桌椅尺寸

复用了现有 KayKit 椅子和矮桌，两类现有人物不换身份、不拉长骨头。住宅默认椅面为 0.400 世界单位，桌面约 0.6，杯子靠各自座位的桌边，水平距离约 0.511。旧桌面过低且过远，真实骨架无法自然触达，单纯提高 IK 强度不能解决。

坐下时将真实臀腿支撑皮肤与实际座面对应；只有鞋底穿地时才有限调整小腿，不强拉悬空的脚。取杯时按人物族有限前倾，再校正手到杯柄的接触；杯子提起后跟随实际腕骨，放下时回到同一桌面位置。说话时使用保留坐姿下肢的上身动作，而不是重新站起来。

同一套家具位置用于客厅和近景。管理端移除、更换为不兼容家具或将桌椅移得过远时，不强行跨房间取杯；降回普通交流。场景刷新、对白下一句和轮询不会反复重启有限演出。

## 验证入口

开发夹具：`/scripts/fixtures/embodied-life.html`，无需账号，不调用 AI，不写存档。

- `?phase=active&family=city&time=6.5`：城市人物在指定秒数的姿势。
- `?phase=active&family=chibi&time=6.5`：Chibi 同一动作检查。
- `&clean=1`：隐藏验收工具条，检查手机原始布局。
- 顶部切换邀请、等待、参与、完成、拒绝、中断及未约成；动画选项可选择跟随系统、减少或完整。

固定时间只在开发构建生效，不是生产调试入口。它不会冻结或推进真实世界时间。

自动检查已接入 Web lint：

- 七个事实阶段、两名演员、120 秒采样和减少动态效果；确认动作最后停稳、拒绝分支不喝东西、杯子不会随离场消失。
- 加载两类实际 GLB 骨架及所选衣服，检查默认取杯目标腕骨误差小于 12 毫米、可见身体与真实座面接触、大腿接近水平、膝盖保持弯曲、鞋底不穿地且骨骼长度不变；另用浏览器独立采样皮肤与家具，不拿求解器的目标值自证通过。
- 家具编辑后接触位置与可用性检查。

这些是逻辑／资产数值守卫，不等价于两分钟连续视觉验收或手机真机性能测试；实际截图和浏览器验证记录由本轮总交接记录补充。

## 明确边界

- 这是一个精细化场景标杆，不是通用全身 IK 或任意物体抓握系统。取杯接触范围围绕兼容的桌椅限定。
- 没有新增手指抓握骨骼动画、真实液体、嘴唇语音同步或物理杯子。杯柄与腕骨对齐不等于每根手指都闭合。
- 现有两套角色比例仍不同，未擅自将玩家人物替换为统一人物；接触误差数值不能保证所有衣服边缘都没有穿模。
- 近景是公开事件阶段的有限展示，不与 AI 每个单词或服务器每一秒严格同步。活动完成仍以服务器真实行动和共同参与时长为准。
- 阅读、做饭等其他生活动作仍沿用既有实现，不能据此宣称所有日常动作都达到这一标准。
