# 视觉升级：第一轮实现与验收

更新时间：2026-09-19。范围：本地前端；未推送、未部署。

## 本轮目标

让玩家先看见「城市与居民的生活」，而不是一层层面板；用统一的光线、材质和构图提高现有素材的质感。这是视觉升级的第一轮，不代表已经达到移动设备的效果极限，也不是把玩法或素材数量减少后换取流畅。

优化前版本已保存为 `1c2472e`（`功能：完善生活对白与人设表达并保存视觉优化前基线`）。本轮新增视觉改动目前保留在本地工作树，未混入该基线提交。

## 玩家能看到的变化

| 场景 | 本轮变化 | 保留的内容 |
|---|---|---|
| 城市 | 画面铺满页面、收紧顶部标题；居民列表使用人物缩略图；云层增加远近层次 | 原有地图、道路、建筑、编辑器与跟随操作 |
| 住宅 | 打开后优先显示大幅室内场景；顶部头像快速定位居民；共餐及资源详情可以收展 | 共餐、房间切换、住宅资源、私人活动与交谈入口 |
| 室内材质 | 统一暖色主光和冷色补光；错缝木地板；家具接地阴影；减少表面塑料感 | 原有室内资产与已编辑的布局，阴影随家具位置变化 |
| 人物 | 住宅、对话、生活片段和角色预览采用共用照明；面部补光、材质粗糙度调整 | 两类人物素材与全部既有自定义选项、动画 |
| 对话 | 依据实际画布比例安排人物和镜头；手机上人物不再偏到屏幕右边；双语在同一个实底气泡中并列对照 | 流式输出、翻译开关、历史回顾与风景浏览 |
| 窄屏住宅 | 默认将公共房间内的居民一起纳入视野；点击头像跟近对应居民 | 手动旋转／缩放后不持续抢回镜头，可用「定位」重新对准 |

长消息仍需在气泡内容区滚动阅读。双语对照不是把整段英文和中文同时无限展开，以免重新挡住人物。

## 画质策略

不再仅凭触屏、CPU 核数或设备内存标签关闭高画质。自动档根据实际画面帧间隔调整渲染分辨率；高低档仍可手动选择。

- 自动档从中档起步，跳过启动暖机和后台暂停；持续顺畅后才提高画质。
- 较慢时降档；升级需要稳定窗口与冷却，反复试升最多两次，避免画面来回变化。
- 渲染分辨率上限按档位为设备像素比的 1／1.25／1.65 倍封顶。
- 城市主要建筑在低档仍有阴影，不再丢弃一半手工摆放物件；高档可以开启城市后处理。
- 城市阴影贴图为低／中 1024、高 2048；室内共用灯光当前固定 1024。
- 修复父组件刷新把自适应分辨率覆盖回初始值的问题；后处理同步跟随实际分辨率。
- Canvas 明确使用当前 Three.js 支持的 PCF 阴影，避免重新配置时恢复到已弃用的旧模式。

本轮没有增加全屏浓雾、强泛光或昂贵 HDR 下载，避免重现城市白雾遮挡。现有木地板使用合并几何，接地遮罩复用一张小纹理，未新增外部美术素材下载。

1. 桌面住宅、客厅居民、卧室、浴室及选中居民的镜头。

3. 同尺寸长英文对话及中文翻译。检查中发现了人物右侧裁切、翻译挤压气泡的问题，修改后再次检查实际画面。
4. 城市加载完成后的模型、云层和阴影；自动档和手动低档正常显示。低档的实际画布像素尺寸确实下降，自动升档后的尺寸也能跨组件刷新保持。
5. 本地真实账号登录后查看城市，再从居民列表进入共享住宅，定位到正在睡觉的居民。未重置账号、未修改密码、未发送测试聊天或主动调用 AI。

这是 **Mac 上的设备模拟，不是真实手机性能测试**。测试场景显示的帧间隔不代表 iPhone／安卓真机帧率，也不代表持续运行时的发热表现。尚未完成所有机型、所有室内编辑布局、8 人同屏及 WebGL 上下文丢失的完整矩阵。

### 本轮发现的本地登录异常

实际账号验收时旧后端进程出现 `sqlite3.DatabaseError: file is not a database`。只读检查 SQLite 文件头正常，`sqlite3 -readonly backend/data/lingolife.db 'PRAGMA quick_check;'` 返回 `ok`。触发现有 `--reload` 重载、重建连接后，原账号可正常登录并加载城市。

没有删除、覆盖、还原数据库，也没有修改后端业务代码或环境配置。证据指向旧连接状态异常，但没有据此确认其最初成因；如果再次发生，应进一步调查文件替换／同步工具／并发进程，不应直接清空数据。

## 无账号复验入口

启动本地 Vite 后打开：

`http://127.0.0.1:5173/scripts/fixtures/visual-review.html`

这是开发验收页，不是新增生产游戏路由。使用虚构居民，复用真实城市、住宅和对话组件；不请求 API、AI 或账号数据库。可切换住宅／城市／对话、四类房间、中英文与画质。城市入场仍会使用浏览器本地的入场标记，不改变存档。

复验顺序：客厅全景 → 头像定位 → 手动拖动 → 再定位 → 共餐详情 → 返回房间 → 各房间 → 长对白翻译 → 城市低档／自动档。等待模型加载完成再判断，不把临时加载占位或隐藏的可访问性降级文本当成最终渲染结果。

## 下一轮仍值得做什么

1. **室内美术与遮挡系统**：按客厅、厨房、卧室分别精修家具比例和动线；镜头前的墙体、灯具可让位。当前只是统一材质与光照，不是重做所有房间布置。
2. **人物与家具接触**：动作与坐垫、桌面、床沿进一步贴合；补脚部／手部 IK、坐姿过渡及表情。当前没有新增骨骼或面部表情系统。
3. **城市街区构图**：做有主次的住宅街、商业街、公共广场样板，再扩展到全城。当前没有重新排布整张地图。
4. **更精细的美术管线**：评估室内烘焙间接光、材质图集与贴图压缩；动态编辑家具时须保留正确的光影更新，不可直接用固定阴影贴图覆盖全部布局。
5. **真机预算**：至少一台 iPhone 和一台中端安卓，连续运行 10～15 分钟；分别测城市、住宅多人、长对话及切场景的帧率／温升／内存，再调档位阈值。

人物列表复用现有静态模型缩略图，不为每个头像创建 WebGL 画布；这轮没有批量重新生成全部头像，也没有保证静态图体现每一项后续换装细节。
