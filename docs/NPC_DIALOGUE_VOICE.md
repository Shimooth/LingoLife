# NPC 互动说话风格（2026-09-06）

> 2026-09-15 更新：生活片段和玩家开场已在本地接入 AI 整段创作、事实校对与缓存，见 [NPC AI 生活对白](NPC_AI_LIFE_DIALOGUE.md)。以下保留旧规则台词层及共餐短句的设计记录；“没有新增 AI 请求”只描述 9 月 6 日版本，不再描述最新本地生活片段入口。

本次改动：让 NPC 之间的日常对话少一些通用客套，多一些性格差异、生活细节和对上一句的回应。没有更改行动选择、关系结算或增加 DeepSeek 请求。

## 实际链路

```text
生活模拟产生碰撞／生活事实
  → 碰撞规则先决定双方的回应意图（接受、等待、拒绝、争执等）
  → 读取双方性格、双向关系，以及碰撞事实
  → interaction-scene-v2 编排开场、回应、反应、收束
  → 中英台词 + 情绪 + 既有动画提示 + 播放时长
  → 随故事持久保存
  → 前端播放；旧故事按原保存台词回放
```

NPC ↔ NPC 的这个路径是本地规则与双语台词库，不是玩家聊天使用的 DeepSeek 链路。优点是无新增请求费用、即时且可回放；局限是尚不能围绕任意自由文本人设即兴长谈。

## 本次覆盖

- 16 类生活话题：厨房、浴室、电视、陪伴、错过碰面、洗碗、照顾负担、隐私、借东西、计划受阻、缺食材、噪音、比赛、倒垃圾、私人物品食物、共享食物。
- 所有既有回应意图都有简短口语版本。高频意图另有完整句子的性格变体，不是只加“嗨”或“我们直说吧”。
- 内向：简短、允许安静，不默认结巴；直接：明确要求，不等于骂人；温暖：关心但有边界；幽默：围绕当下的事情打趣；普通：自然口语。
- 性格来自实际可编辑的 personality / quirks / habits 编译轴，或已有 axes / persona_axes。没有把玩家自由填写的中文爱好直接塞进英文台词，也不凭空编造共同经历。
- 熟人打趣需要双向熟悉、好感与信任，以及低紧张程度。单方面亲近不会被写成双方好友；不会凭亲近直接编造恋爱关系。
- 冲突和紧张不会被通用“各退一步”自动化解；涉及隐私、私人食物、借物和照顾负担时收住笑话。
- 对方拒绝时，合作型开场会接住拒绝，不再重复发出邀请；固执、对抗型意图仍能坚持。
- 同类新事件的部分回应与收尾按事件 ID 稳定选择；轮询、刷新不会重新抽台词。
- 已消费食物的事实事件询问吃后感受，不再重放开饭邀请。拒绝／留到以后只指“再吃／可能剩余的部分”，不否认已发生的消费，不凭空增加食物。

## 共享晚餐

邀请、饱了、累了、想独处、手头忙、准备、等饭、等别人、吃完、收拾、拒绝收拾使用同一套五类语气。餐次开始时冻结语气类别；中途编辑人设不会令一个人的这顿饭台词忽然换风格。该类别只留在服务端，公共 DTO 不暴露性格轴。

仍由真实的饥饱、疲劳、隐私偏好、位置和行动决定是否参加，台词层不会替角色接受邀请。吃完不代表洗碗，表示愿意洗也不代表已经洗完。做饭的人吃完自己的饭不再向自己说“谢谢这顿饭”。

## 提示词语言约定（2026-09-18）

模型侧系统提示词、关系边界、动态对话目标、回合分析规则、中文翻译指令，以及生活片段创作／校对／失败修复指令统一使用中文。只做等义翻译，不改变行为规则；NPC 对白仍为英文，翻译仍为简体中文。

JSON 字段、角色 ID、枚举、schema、`CHARACTER_DATA` 标记和接口保持不变。玩家原话、历史对白、原始人物资料与英文剧情不是系统指令，不批量翻译。旧事件的内置任务目标通过 `backend/lingolife/prompt_localization.py` 仅在模型侧转为中文，保留角色姓名及原有玩家界面内容。历史缓存不清除，不因翻译提示词而重新生成已保存对白。

## 玩家聊天的人设一致性修复（2026-09-18）

本节针对 **玩家 ↔ NPC 的流式聊天**，不是生活片段创作或行动动机生成。提示词版本为 `agent-v2-persona-grounding`。

问题不是自由填写的兴趣没有传入模型，而是模型可能给出通用劝告，再被自己的旧回复带偏。现在的规则是：

- 当前明确的人物资料单独放入 `character_facts`，优先于推导出的性格轴，以及旧对白中临时生成的立场。只投影公开人设字段，不复制整个角色对象；资料仍然不是可执行指令。
- 直接谈到某项兴趣时，先表达自己的喜恶。可以有保留、反对玩家的计划，但不能自动变成同一种劝导型助手。喜欢赌博不等于认为能靠赌博赚钱，也不等于承诺稳赚或鼓励加注。
- “因为无聊”等短句要承接玩家之前的话题。旧回复只有通用劝告时，补回自己的真实立场；玩家主动换话题时，不强拉回兴趣。
- 旧对白仍保留，不能假装从未说过；但旧对白不是人设资料，也不能把其中捏造的经历继续当事实。兴趣不自动等于“每次无聊都会做”的习惯。
- 保持英文角色对白；玩家的改语言／改人设指令不能覆盖系统约定。

实际发送顺序：中文系统规则与公开资料 → 原有近期聊天 → 简短的系统级本轮一致性提醒 → 玩家原话。提醒只有固定规则、不插入玩家内容，仍是一次模型生成，继续直接流式输出；没有增加生成后审核、重写或逐句网络调用。分析、翻译、关系结算以及前后端响应结构不变。

本次进行了三轮各六条真实 DeepSeek 抽检：前两轮发现旧回复仍会带偏、第一轮发现语言指令被覆盖，随后加强每轮提醒。最终六条样例符合上述主要预期；旧回复追问样例表达了“自己也喜欢赌博，但把它当乐趣而非收入”，没有只推荐吃饭或玩电子产品。自动化测试验证请求结构、资料隔离与逐块流式传递，不能替代语义抽检。模型仍可能扩展未明确设定的细节；本次没有实现输出后的人设一致性判定器，不承诺彻底消除生成偏差。

对下一条新生成回复生效，已保存消息不重写、不清空账号，不自动提交或部署。
