# 天空之城美术与渲染 QA 基线

版本：0.1

参考：KayKit City Builder Bits `sample.png`（1920 × 1080）

用途：约束天空之城重构的构图、灯光、材质、性能和回归测试；不是场景实现说明。

## 1. 参考图真正好看的原因

参考图不是把全部素材平均铺满，而是一个专门为镜头编排的微缩城市：

- 城市主体约占画面宽度 `74%`、高度 `69%`，四周有清楚的负空间。
- 最高建筑约占整张图高度 `30%`；即使在总览中，窗、雨棚、路沿和车辆仍然可辨认。
- 主要可见建筑约 `14–18` 栋，每个街区 `3–5` 栋；后排较高、前排较低，不是等距棋盘。
- 道路约占城市投影面积的 `32–38%`，建筑及其底座约占 `40–48%`，其余空间留给人行道、道具和呼吸感。
- 一屏约有 `7–10` 辆车、`8–14` 个路灯/交通灯以及少量消防栓、垃圾桶、货箱、长椅和盆栽。细节沿道路聚集，不均匀撒点。
- 屋檐、窗框、车辆与路缘拥有明显但柔和的接触阴影；主光有方向，暗部仍有偏冷的天空补光。
- 色彩来自资产原始贴图，暖橙、红、芥末黄与冷蓝灰、绿色交替，相邻建筑避免连续同色。
- 镜头接近正交微缩视角；道路平行线几乎不汇聚，屋顶和正立面同时可读。

因此验收重点不是“模型数量越多越好”，而是模型在最终屏幕上的尺寸、层次和接地感。

## 2. 天空之城构图目标

### 2.1 默认桌面总览

| 项目 | 目标 | 不通过条件 |
| --- | ---: | --- |
| 城市平台投影宽度 | 画布的 `80–92%` | 小于 `72%`，视觉像远处地图 |
| 城市平台投影高度 | 画布的 `72–86%` | 为完整展示边界而缩得过小 |
| 最高建筑屏幕高度 | `15–24%` 画布高度 | 小于 `11%`，窗和雨棚不可读 |
| 主视觉建筑数量 | `14–22` 栋 | 超过 `28` 栋且没有明确前后层次 |
| 主路屏幕宽度 | `55–90 px`（1080p） | 低于 `40 px` |
| 画面安全留白 | 每边 `5–10%` | UI 压住主建筑或所有边都塞满 |
| 道路出口 | `3` 个，至少 `2` 个在默认镜头明确可见 | 道路在平台内闭环，仍像孤岛 |

总览允许平台或道路出口轻微超出画面，不应为了看见每一个边角而牺牲建筑尺度。地图可拖动和平移，默认镜头只负责给出最有吸引力的首屏构图。

建议正交镜头方位：

- 水平方位角 `38–45°`。
- 相对地面的仰角 `32–36°`。
- 目标点略偏城市核心后方 `z = -1 ~ -3`，让前景道路与低楼形成引导线。
- 1080p 首屏垂直可见世界范围约 `28–34` 单位；不要回到当前约 `46–50` 单位的远景尺度。
- 聚焦地点后垂直可见范围约 `12–17` 单位，飞行时间 `650–900 ms`，使用 ease-out 或阻尼，不改变相机投影类型。

### 2.2 城市平台与云层

- 平台是有厚度的浮空城市基座，不再出现海水、沙滩、港湾或闭合海岸线。
- 平台正面厚度建议 `0.9–1.5` 世界单位；顶部偏暖灰，侧面降低亮度 `20–30%`，底面再降低 `15–20%`，产生悬浮体积。
- 三条主路延伸到平台外 `6–10` 世界单位并进入云层；出口不做断头路，可在远端逐渐被云遮挡。
- 云只包围平台边缘和道路远端，中心 `70%` 的屏幕区域必须保持干净。
- 默认镜头中云的总覆盖面积控制在 `15–28%`；单个云团使用 `3–7` 个有尺寸差异的团块，不铺成均匀白色环。
- 近景云最高点应低于城市顶面至少 `0.35` 单位；任何云都不得穿过默认相机与城市中心之间。
- 优先使用不透明或 alpha-test 云材质并正常写入深度。禁止大量 `transparent + depthWrite=false` 球体互相叠加，这正是“整层白雾”的高风险做法。
- 首版不启用 Three.js `Fog/FogExp2`。天空深度由渐变背景、平台高度差和云团层级表达。

### 2.3 街区节奏

- 一条英雄主街承担约 `35–45%` 的建筑和细节，另有两条次路，不再使用覆盖全平台的均匀网格。
- 每个街区 `3–5` 栋建筑；相邻立面留 `0.15–0.45` 个道路宽度，不要互相穿模，也不要产生空旷草坪。
- 后排优先 C/G/H 等高体量，前排优先 A/B/D/E/F 等较低体量。
- 相邻建筑尽量不使用相同模型；同型号连续出现不得超过 `2` 次。
- 每 `2–3` 个道路模块安排一辆车或一组街道道具，但同一路段保留至少 `30%` 无道具区域。
- 弯道、T 型路口、普通转角和斑马线都应出现。推荐一屏 `3–5` 个路口、`2–4` 处斑马线、`2` 个以上弯道。
- `building_*_withoutBase` 只用于已有连续人行道/统一基座的区域；否则使用带底座版本，避免建筑悬空。

## 3. 灯光与色彩目标

推荐默认午后参数范围：

| 层 | 参数 |
| --- | --- |
| 主方向光 | 暖白 `#ffe4bd`，强度 `1.6–2.2`，方向从相机左前上方，位置可从 `[-18, 28, 16]` 起调 |
| 天空补光 | Hemisphere sky `#d9efff` / ground `#586558`，强度 `0.42–0.62` |
| 全局环境光 | `0.08–0.18`；不要与高强度 Hemisphere 同时把阴影抹平 |
| 环境反射 | `Environment` 仅影响环境、`background={false}`，分辨率 `128`（移动）/`256`（桌面），强度 `0.55–0.8` |
| 色调映射 | 优先 `ACESFilmicToneMapping`，曝光 `0.98–1.08`；若暖色明显灰化，再 A/B `NeutralToneMapping`，不要叠加 CSS filter |
| 背景 | 上方天空蓝 `#80b9d7`，地平线浅青 `#d7eced`，云暖白 `#fff7e8`，避免纯白背景 |

阴影：

- Canvas 使用稳定的 `PCFSoftShadowMap`（R3F 可设 `shadows="soft"`），不在运行中切换阴影算法。
- 桌面主光 shadow map `2048`；移动端 `1024`。阴影相机只包围可见平台，建议边界比城市包围盒多 `2–3` 单位，禁止固定成远大于城市的范围。
- 初始建议 `shadow.bias = -0.0002 ~ -0.0005`、`shadow.normalBias = 0.02 ~ 0.05`、`shadow.radius = 2–4`，最终用屋顶和人行道截图检查 acne 与漂浮。
- 可用现有 Drei `ContactShadows` 补接地：桌面 `resolution=1024, opacity=.30–.42, blur=2.2–3.0, far=7–9, frames=1`；移动端 `512, opacity=.25–.34, blur=2.0–2.6, frames=1`。
- `AccumulativeShadows` 会为整座城重复渲染许多帧，不适合这个大场景；`SoftShadows` 会全局改写 shader，挂载时触发重新编译，也不作为首选。

最终画面应满足：白色屋顶仍有纹理和边缘，不剪成纯白；道路暗部不低于近黑；建筑底座和轮胎下存在明确接触阴影；树、车和灯柱都不呈现“贴上去”的感觉。

## 4. 后期处理决策

当前依赖能力核对：

| 效果 | 当前依赖 | 本轮决策 |
| --- | --- | --- |
| Environment / Lightformer | `@react-three/drei` 已提供 | 可使用，`frames=1`，不加载外部 CDN preset |
| ContactShadows | Drei 已提供 | 高低画质都保留，不同分辨率 |
| PCF soft shadow | R3F / Three 已提供 | 使用 |
| AdaptiveDpr / PerformanceMonitor | Drei 已提供 | 可用于有迟滞的自动降级 |
| SSAO / GTAO | Three 底层有 pass，但项目无声明式 composer | 本轮不接；ContactShadows 先解决主要接地问题 |
| 景深 / Tilt shift | 当前无 `@react-three/postprocessing` | 本轮不接 |
| Bloom | 当前无稳定后期栈，参考图也没有明显发光体 | 本轮不接 |

景深不是宣传图质感的核心，贸然添加还会再次造成移动端人物模糊、WebGL 与 DOM 标签清晰度不一致。本轮先靠正确镜头尺度、接触阴影、光照和构图达到质感。如果以后增加景深，只允许桌面高画质使用，模糊半径不超过 `1.5 px`，人物、当前建筑和互动标签必须位于清晰焦平面；移动端始终关闭。

## 5. 桌面与移动画质档

| 参数 | 桌面高画质 | 移动/低画质 |
| --- | ---: | ---: |
| DPR 上限 | `1.75–2.0` | `1.5`，持续掉帧后最低 `1.0` |
| 主阴影 | 2048 PCF soft | 1024 PCF soft |
| ContactShadows | 1024 / frames 1 | 512 / frames 1 |
| Environment | 256 / frames 1 | 128 / frames 1 |
| 城市内容 | 全部保留 | 全部建筑与道路保留，只减少重复小道具和远云分段 |
| 云动画 | 极慢整体漂移 | 静态或每个云团一个低频位移 |
| 后期 | 本轮无 | 无 |

移动端不能简单“看见整张 52 单位地图”：允许平台宽度达到视口的 `105–130%` 并通过拖动浏览。360 × 640 视口中，核心建筑高度至少 `45–75 px`，至少同时能辨认 `3` 个业务地点。

自动降级必须有迟滞：例如连续 `2–3 s` 低于 `36 FPS` 才降一级，连续 `5 s` 高于 `52 FPS` 才恢复。不得按单帧波动切换 DPR、阴影或 Environment，否则会出现屏闪和 shader 抖动。`AdaptiveDpr` 不使用 `pixelated` 模式。

## 6. 防白雾、防屏闪、防模糊硬门槛

### 6.1 白雾

- 不存在覆盖视口的大型半透明 Three 网格。
- 云材质默认 `transparent=false`、`depthWrite=true`；必须透明时优先 `alphaTest`，且透明层数不超过两层。
- 不启用全局 Fog。
- 默认相机到目标点的线段与所有云包围盒都不相交。
- Drei `Html` 不使用 `distanceFactor`；覆盖层不得生成接近视口大小的 transform surface。

### 6.2 屏闪

- 加载遮罩必须等世界关键 GLTF、首个角色和 shader 完成后，再等待两个完整合成帧才单向淡出；Canvas `onCreated` 不能单独代表资源已准备好。
- 加载遮罩背景与 WebGL clear color 要在 RGB 每通道相差不超过 `12`，避免切换瞬间白/绿闪烁。
- `ready` 是单调状态：一次变为 true 后，普通 Suspense、画质降级或角色加载不得重新盖回全屏遮罩。
- 画质档、ToneMapping 和 shadow type 在一帧内只初始化一次，不随 FPS 往返切换。
- WebGL context lost 时显示 DOM 降级界面，不能保留最后一张发白 Canvas。

### 6.3 移动端清晰度

- CSS 不给 canvas 或其父级使用 `filter: blur()`、`backdrop-filter`、opacity 淡入叠层。
- Canvas CSS 尺寸与容器实际尺寸一致，不通过 transform scale 放大低分辨率画布。
- 初始移动 DPR 至少 `1.5`；只有实测持续掉帧才降到 `1.25/1.0`。
- 对话人物、当前角色及选中建筑不参与任何 DOF/景深。
- 在 `390 × 844 @ DPR 3` 的真机或模拟设备截图中，人物眼睛/发型轮廓、建筑窗框和斑马线都必须可分辨。

## 7. 发布前截图矩阵

每次地图美术调整至少保留以下截图并并排比较：

1. `1440 × 900`，默认午后总览，高画质。
2. `1440 × 900`，聚焦商业建筑，确认招牌、窗框和接触阴影。
3. `390 × 844`，默认移动总览，低画质。
4. `390 × 844`，聚焦一个居民，确认人物没有被云或建筑遮挡。
5. `390 × 844`，冷启动从 loading 到首帧的录屏，逐帧检查白/绿闪。
6. `prefers-reduced-motion: reduce`，确认静态云、镜头和加载状态仍能正确出首帧。
7. WebGL context lost/禁用时，确认 DOM 地点及居民列表可操作。

截图验收应同时看以下区域：屋顶高光、楼体暗面、建筑底座、车辆轮胎、云与平台边缘、三条道路出口、HTML 标签和被选中居民。只看“整体有没有显示”不算视觉验收完成。
