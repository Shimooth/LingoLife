# 共享住宅生活表现：第一轮

日期：2026-09-06。仅本地实现，未部署。

## 本轮边界

后续 P0＋P1 已新增可提议、可拒绝、可追踪结果的共餐行动链，见 [新人实操引导与室友共餐](SHARED_MEAL_VERTICAL_SLICE.md)。下文的动作素材与手部接触边界仍然适用。

本轮不是另建一套演示世界：真实引擎的当前行动驱动室内表演，食物、分享与餐具由服务端事实驱动画面。客户端坐下、拿持、停顿和视线是表现层，不创建关系变化，不结算行动，也不调用 DeepSeek。

### 行为连续性

- 家里有自己做的或明确可分享的饭菜时，提高吃饭倾向、减少重复做饭；只在家中生效，日程和紧急需求仍有优先权。
- 愿意照顾人的厨师可多准备一份，消耗额外库存；并非所有人都分享，也不强制室友接受。
- 吃完留下真实餐具痕迹。爱整洁者更愿意顺手收拾，疲惫或随性者更可能留到以后。
- 单个盘子不是一个冲突；积累到阈值才进入既有责任/碰撞系统，避免每顿饭都升级为争吵。
- 新增只读 `household.life`：可分享饭菜的公开制作者和数量、待收拾餐具数量。排除私人食物、隐藏分数与其他住宅的数据。

### 动作与空间

- 从已经下载的 KayKit Character Animations 1.1（CC0）提取 12 条不带网格的源动画，包含坐下/坐着/起身、招手、拿持、交互与工作动作，合计约 490 KB JSON；无需新下载或付费。
- 按目标绑定姿态重定向城市居民与 Chibi。城市骨架的侧向 bind pose 单独校准；保留骨长和原始缩放，仅迁移必要的垂直骨盆位移，去掉水平 Root Motion。
- 坐姿和上半身动作组合成吃饭、阅读；做饭采用台面工作动作，不把劈木头的 `Chopping` 当成切菜。
- 小型杯子、勺子、木质工具、书、抹布挂在实际手骨上；台面操作使用旋转型手部接触校正，不拉长手臂。
- 房间内变更活动点时按家具占地生成网格路线，走过去并转身；起身与坐下单独衔接。无路时不穿越家具。
- 没有合适座位时采用站立动作，不在空中坐下；不会因人数增加而把居民缩小。
- 真实社交行动的双方可互相看一眼；不把视线反馈伪造成新对话或关系结算。
- 厨房锅具/少量蒸汽只在做饭时出现；餐具由事实显示和清除。默认与管理端修改后的家具位置均参与定位。
- 住宅概况新增放大观看，支持室内拖动/缩放；减少动态效果设置下保持静态姿态。

## 如何查看

### 室内外存在规则（2026-09-06 后续打磨）

城市 DTO 增加只读 `spatial_presence`：`mode` 为 `indoor` / `outdoor` / `traveling`，并提供公开城市 `location_id` 与 `building_id`（室外/路上为空）。它描述当前位置，不把行动目的地当作已经到达；不公开私人卧室或浴室锚点。

- 住宅、图书馆、咖啡馆、医院、办公室等明确室内地点：不绘制城市人物模型、脚圈、头像或状态标记。建筑和居民列表仍保留，列表显示“室内 · 地点”。
- 公园、广场、步道、露天市场以及尚未能明确区分室内的混合地点：仍显示室外居民。具体室内白名单维护在 `backend/lingolife/spatial_presence.py`，不能只因有建筑模型便推定整个地点都在室内。
- 计划出门不等于已经出门；跨建筑 `traveling` 才进入室外行走。同住宅换房间仍属于室内。
- 地图保留完整居民集合用于住宅布局，仅过滤室外 actor 层，避免居民进屋后连住宅一起消失或布局跳动。
- 居民列表点击在家的角色，打开住宅；点击在其他建筑里的角色，打开对应地点详情。跟随者到达建筑后也切到对应入口，不继续跟随隐藏人物。
- 回家路线解析住宅入口；生活行为没有旧事件 ID，依然按行动实例通知到达并刷新服务器。减少动态效果时也通过计时器刷新。最终到达由服务器确认，前端不擅自完成行动。
- 住宅室内演员使用同一存在信息，已出门但后端原始坐标仍指向出发住宅的人不会继续留在厨房。

验收：`backend/tests/test_spatial_presence.py`；`npm --prefix web run check:spatial-presence`；独立 Chrome 与开发服务器启动后运行 `npm --prefix web run check:spatial-presence-browser`。无账号夹具为 `/scripts/fixtures/spatial-presence.html`，不请求真实 API、不改账号状态，不是生产入口。

真实玩法：完成居民创建后，在城市打开共享住宅，选择厨房/客厅，点“放大看看他们的生活”。居民是否在家、是否吃饭由实际日程决定，不为演示强制改写账号。

## 2026-09-07：人物在房间里生活，不因私人活动消失

按用户最新选择，撤销“私人活动不展示人物与具体房间”的表现规则。隐私限制保留在内心、意图、秘密、资源目标和打断权限层面，不再令可观察的物理人物消失。

- 城市地图仍不绘制室内人物；点击居民直接进入其住宅房间。
- 公共 DTO 的 `current_room_id` 提供实际房间的展示 ID（浴室、卧室等）；不公开内部床位路径或隐藏资源目标。`visible_context.visibility`、private interruptibility 与意图脱敏规则不变。
- 私人活动也显示室内人物。卧室按完整居民名单与固定 `private_room_id` 归属选择房间，不能按当前可见人物重新分床。
- 睡觉时使用床上的横卧造型、被子和轻微呼吸；洗澡保留着装模型并用不透明遮挡围住身体，不添加裸露素材。没有伪造新的骨骼动画资源。
- 点击卧室居民时镜头靠近其房间；保留角色定位圈、手动查看其他房间以及重新定位入口。
- 观看私人活动不自动结束行动或开放“交谈”按钮。是否在家仍由服务器的实际位置决定。

验证入口：`node web/scripts/check-household-location-browser.mjs`，覆盖卧室人物、固定床位、过滤／重排不换床、睡觉、洗澡、公共房间、移动端和语言切换。无真实账号写入。

### 床铺贴合、状态区分与洗浴蒸汽（2026-09-07）

- 睡姿按床模型的床垫高度及预览变换重新对齐；被子改为带弧度和下垂边缘的网格，边缘落在床垫附近。仅对当前睡眠模型的独立材质裁切被覆盖部分，避免衣物、手脚穿出被面。城市与 Chibi 分别校准高度和尺度，保留轻微呼吸并遵循减少动态效果设置。
- 地图居民状态明确显示睡觉或洗澡，不再统一写“处理私人事务”；安静休息仍为独立 `rest_alone` 行动，与做饭、阅读等不同。准备、等待、被打断、放弃和完成显示各自阶段，不提前展示进行中的睡姿。房间人数说明也分开统计睡觉、休息、洗澡和其他活动。
- 浴室用不透明核心＋柔和边缘的雾团遮住着装身体、露出头部，替代整圈硬质遮挡；未增加裸露素材。两类体型单独设置雾团高度。
- 以上是物理状态展示，不开放私人行动的打断权限；提供给 AI 的私人行动上下文仍保留原来的概括与脱敏规则，不传递隐藏意图和资源目标。
- 本地验证：Backend 全量 604 项通过，阶段补充后专项 21 项通过；Web lint/typecheck/build 通过。无账号浏览器回归增加被面高度／弧度／裁切启用／蒸汽存在断言，人工查看城市与 Chibi 的睡眠、洗浴截图；原定位、8 床归属、手机与语言检查继续通过。仅本地，未提交或部署。

无账号动作验收：开发服务器 `/scripts/fixtures/household-life.html`。这个明确隔离的测试页可切换模型和行动，不调用账号 API，不生成真实游戏结果，不打进生产入口。

## 尚未完成的品质项

这是生活动作的首轮纵切，不宣称每个动作都已达到最终成品质量。尚未实现精细唇部咀嚼、逐口食物体积消耗、双手递接的完整同步、端盘跨房间的连续演出、全身通用 IK、生活音效与逐个体型的手工动画修型。现有“吃饭/阅读”仍是源动作组合；只有台面右手使用接触校正，不能据此声称所有物件都有准确抓握。

下一轮应优先检查最常用体型的椅面/手部接触、多人同时占用空间的避让，以及真实玩家观察到的生活节奏；不继续靠增加状态文案替代动作。
