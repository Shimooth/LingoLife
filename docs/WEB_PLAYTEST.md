# Web Demo 小规模玩法测试

## 目的

用 5–10 名目标用户验证：角色处境是否能驱动玩家持续用英语交流，以及状态变化和英语反馈是否帮助而不打断沉浸。测试产品假设，不测试 Unity、画面品质或完整课程体系。

## 测试前准备

1. 用无痕窗口打开公网 Web 地址，确认初始状态、发送、刷新恢复和错误提示可用。
2. 为每名测试者分配匿名测试编号；不收集姓名、邮箱或工作单位。
3. 准备事件记录：打开时间、首次发送时间、对话轮数、发送成功/失败、结束时三个数值。
4. 告知测试者对话会由 AI 处理；不要输入密码、联系方式或敏感个人信息。

## 主持脚本（10–15 分钟）

开场只说：

> 这是一个用英语和虚拟角色相处的早期版本。请像平时使用产品一样体验；遇到不理解的地方先说出来，我暂时不会指导。

随后：

1. 发给测试者 Web 链接，不解释三个数值和操作方法。
2. 观察 8–10 分钟；只记录行为，不纠正英语，也不提示该说什么。
3. 如果卡住超过 60 秒，只问“你现在期待发生什么？”并记录原因。
4. 体验后进行 3–5 分钟访谈。

## 访谈问题

按顺序询问并尽量记录原话：

1. 刚才你觉得 Emma 发生了什么？你为什么那样回复？
2. 哪一刻让你最想继续或停止聊天？
3. 关系、心情、英语经验分别代表什么？哪次变化让你困惑？
4. 英语反馈有帮助吗？它有没有打断你和 Emma 的对话？
5. 如果明天 Emma 有新进展，你会回来吗？为什么？
6. 你下一次最希望看到什么变化？只能选一项。

避免问“你喜欢吗”或直接展示待开发功能列表，以免产生迎合性回答。

```text

```

## 汇总与决策

测试结束后按 [DEMO_MVP.md](DEMO_MVP.md) 的六项指标汇总人数与比例，并把问题分为：角色/内容、反馈呈现、交互、稳定性。优先修复阻断首次发送和三轮闭环的问题，再做一轮同规模测试。

- 达标：核心循环、角色牵引和稳定性均达到门槛，可讨论扩大内容与恢复高表现力客户端。
- 部分达标：继续只迭代 Web 的情境、提示与反馈，不增加 NPC 或长期系统。
- 未达标：重新审视核心假设；不要用更重的客户端制作掩盖玩法问题。
