# P0 内测运营手册

## 范围与入口

P0 的目标是让每次测试都能归属到可管理的账号，并知道互动量、AI 用量和基础留存，而不是立刻
建设完整商业账户体系。

- 玩家端：`https://lingolife.shimooth.me`
- 管理端：`https://lingolife.admin.shimooth.me`
- 身份：一次性邀请码 + 全局唯一用户名
- 运行：同一个容器、同一个 SQLite 数据库；两个域名各自同源访问 API

邀请码只证明有资格注册，不是长期密码。邀请码兑换后即失效，用户名不可与已有账号重复。玩家
应保存浏览器登录状态；清理浏览器数据或换设备后是否可恢复账号取决于后续登录恢复功能，P0
测试前需明确告知参与者。

## 日常内测流程

1. 管理员登录管理域名并创建所需数量的邀请码；每码只分配给一名测试者。
2. 记录邀请码的分发对象时使用内部编号，不要在普通群聊公开批量邀请码。
3. 测试者在玩家端完成邀请码注册/登录；首次账号先阅读介绍，创建并确认 2～8 名居民后进入天空之城。少于 2 名时停留在建组流程，不以默认单角色跳过。
4. 管理端观察注册、最近活跃、对话请求、AI 成功/失败和额度消耗；默认避免浏览完整对话正文。
5. 对异常账号可停用、调整额度或撤销未使用邀请码，并记录操作原因。
6. 每轮测试结束导出聚合指标、记录版本号，再决定是否扩大样本。

推荐每天查看：新增账号、DAU、每用户对话轮数、次日回访、请求失败率、DeepSeek token 与估算
成本、达到额度上限的人数。测试结论必须注明样本量和版本，避免把开发者自己的流量计入用户数据。

兼容例外：schema v3 之前已经实际存在的单 Emma 账号为避免被升级锁定，可以继续进入；它不代表新账号规则，并应收到“补足第二名居民”的迁移提示。新注册账号和迁移后才首次物化 Emma 的账号不能使用该例外。

## 可重复的新用户流程测试账号

固定保留用户名 `onboarding-test` 作为跨设备的新手流程测试账号。账号只需通过邀请码注册一次；此后在任何设备上都使用用户名和密码登录，不再重复填写邀请码。需要从头测试时，在管理端找到该账号，点击“重置存档 / 新手流程”，并再次输入完整用户名确认。

重置只删除该账号的角色、对话、关系、事件、学习、共享住宅、生活世界和引导进度；账号、密码、已兑换邀请码、登录资格、AI 额度、用量和审计轨迹继续保留。服务端只允许重置 `onboarding-test` 或 `onboarding-test-*`，普通账号会被拒绝。

不同开发机的本地 SQLite 数据库互不共享；本地需要单独创建同名账号。生产账号保存在 VPS 持久化数据库中，不随 Git 发布包替换。Git 只记录本节的非敏感约定，禁止提交 SQLite 数据库、密码或密码哈希、邀请码、Session Token 和管理凭据。测试账号密码应保存在个人密码管理器中，而不是仓库或交接文档中。

## 额度与滥用控制

额度由服务端判定，前端显示只用于反馈。内测默认可采用每天 30 次、每分钟 5 次，测试账号或
特殊访谈通过管理员操作追加额度。邀请码、用户名和客户端请求头都不能作为管理员凭据。

管理密码不得与 VPS、GitHub 或 DeepSeek 密码复用。连续失败登录应限速；公网管理端即使域名
不公开也视为可被扫描。管理员只在自己的设备登录，结束后退出，不通过截图或聊天传递秘密。

## 数据与隐私

收集前应向参与者说明记录内容、用途、保存期和删除方式。账号列表默认展示用户名、状态、额度与
聚合使用指标；完整聊天正文属于更敏感数据，应最小化访问并避免复制到工单或聊天工具。日志不得
记录邀请码、管理密码、会话 Cookie、DeepSeek Key 或完整 Authorization 值。

若用户要求退出内测，先停用账号，再按约定删除或匿名化个人数据。删除前确认是否影响聚合统计，
需要保留的分析数据应去标识化。生产数据操作前先执行一致性备份，备份的访问权限和保留期与主库
同等管理。

## 发布检查表

- 两个域名均为有效 HTTPS，HTTP 自动跳转 HTTPS。
- 玩家域名无法进入管理页面；管理接口未认证时不返回账号数据。
- 邀请码只能成功兑换一次；重复用户名被明确拒绝。
- 普通玩家不能创建邀请码、查看其他账号或调整额度。
- 普通玩家和普通运营账号不能进入城市/住宅布局作者工具；布局作者权限单独授予并记录审计。
- 新账号 0/1/2/8/9 人边界正确，2～8 人全部进入同一共享 Household/Residence。
- 旧单 Emma 兼容账号可继续且有补足提示，新账号不能伪装成兼容账号绕过 2 人门槛。
- 旧账号迁移不丢失角色、关系、消息、记忆、事件或学习记录；超限账号不会被静默删除。
- Cookie 安全属性、登录限速、退出登录均验证。
- AI 请求与额度扣减具备请求 ID，失败请求不会错误重复扣费。
- 部署前备份数据库；发布后验证健康检查、注册、聊天和管理只读查询。

部署、备份、迁移与回滚命令见 `deploy/README.md`。
